# 02 · 需求规格

## 2.0 约定

- 优先级：P0 必须（MVP）、P1 应该、P2 可选。
- 每条需求给出可验证的验收要点（Acceptance）。

## 2.2 非功能需求

### 2.2.1 性能（NFR-PERF）

- 常驻 CPU 均值 < 5%、内存 < 300MB。
- 截屏缩略图 ≤ 1280px、JPEG q≈70；分析期间主线程不卡顿。
- 冷启动 < 3s；立绘懒加载（首屏仅预载 5 张常用姿势）。
- 粒子/动画存在数量上限，自动回收。

### 2.2.2 隐私与安全（NFR-PRIV）

- 默认零联网：未配置模型时应用不发起任何外部请求（可在断网下验证）。
- 无遥测、无统计上报。
- 截屏默认仅保留最新一张或关闭；事件仅存本地。
- API Key 本地存储、界面不回显；日志不打印密钥。
- 上下文隔离 contextIsolation=true、nodeIntegration=false、sandbox=true，渲染层仅通过白名单 IPC 访问主进程。

### 2.2.3 可靠性（NFR-REL）

- 模型调用超时 15s、重试 1 次、失败降级本地逻辑。
- 截屏失败静默重试，连续失败不弹窗。
- 存储写入异常时内存缓冲，不崩溃。
- 重启后恢复窗口位置与养成数据。

### 2.2.4 兼容性（NFR-COMP）

- Windows 10/11（21H2+），x64。
- Electron 37 稳定版；Node 运行时为 Electron 内置。

### 2.2.5 可维护性（NFR-MAINT）

- 桌宠状态机为纯函数模块，与表现层分离，可单元测试。
- 台词、立绘映射、关怀规则均为数据/配置，改动无需改逻辑代码。
- 模块边界清晰：窗口管理 / 上下文引擎 / 关怀 / 存储 / 渲染各自独立。

### 2.2.6 成本约束（NFR-COST）

- 默认零 API 成本（本地启发式）。
- 提供成本模型与统计（见 04），帮助用户在「频率×模型价格」之间权衡。

## 2.3 MVP 边界

MVP = 全部 P0 项：FR-PET-01/02/03/04/05/07/08/10、FR-CTX-01/02/04/05/06/07、FR-AI-01/02/03/04、FR-CARE-01/02/04、FR-GROW-05、FR-SYS-01/06/07。P1/P2 按里程碑顺序加入。
