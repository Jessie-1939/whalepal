# 12 · 记忆介质决策：长期记忆用文本，像素只是原料

> **问题**：既然单张图片可能更小、信息量又远大于文本，为什么不直接用图片做长期记忆？
> 本文用本机实测数据把结论钉死，并给出唯一例外与对应的可选项。
> 实现：`src/main/context/stats.js`（体积统计）、设置 → 数据 → 「记忆体积」（随时复算）。

## 12.1 先量数（本机实测，1280×720 JPEG q72）

| 单位 | 大小 |
| --- | --- |
| 一张截图 | **87.4 – 136.2 KB**（随屏幕内容浮动，两次实测） |
| 一条文本记忆（事件） | **323 B**（30 条 / 9.5 KB） |
| 两者比 | **1 张图 ≈ 270 – 432 条文本记忆** |

## 12.2 四个维度的对比

### ① 存储：图片从来没有"更小"

| 方案 | 每月体积（按 300 条事件/天估算） |
| --- | --- |
| 文本记忆（事件 + 摘要 + 对话） | **≈ 2.9 MB/月**（1000 条/天也仅 9.7 MB/月） |
| 图片：去重后按事件存（≈300 张/天） | ≈ **78.7 MB/月** |
| 图片：60s 全量存（1440 张/天） | ≈ **3.78 GB/月** |

图片只有在"描述一屏内容所需的文本字节 > 图片字节"时才更小——而一屏密集文字完整 OCR
约 6–15 KB，仍然只有 87–136 KB 的 **1/6 ~ 1/22**。也就是说：连最"文字密集"的屏幕，
文本化后都比图小一个数量级，更不用说普通工作流（代码、文档、浏览器）。

### ② 信息量：要区分"原始比特"和"可用信息"

- 香农意义：87 KB 图 ≈ 70 万 bit；323 B 文本 ≈ 2.6k bit——**图片的原始比特确实多得多**。
- 但记忆的价值 = **检索时能用上的信息**。我们的问答是"我在干嘛 / 忙了多久 / 做了什么"，
  这些语义（谁/什么/何时/多久）全部由事件捕获；截图里 99% 的比特是渲染像素、空白与噪声，
  对检索毫无贡献。
- 所以按「**每字节可用信息量**」计量：**文本高一个数量级**。这不是文本"更聪明"，
  而是屏幕上下文的信息主体本来就是文本（UI 状态、标题、文档、代码）。

### ③ 召回成本：图片记忆把成本推给每一次回忆

| 一次问答携带 | Token 量级 | 用百炼 Flash 价（输入 0.8 元/M）估算 |
| --- | --- | --- |
| 40 条事件（文本层） | ≈ 4k tokens | ≈ 0.003 元/问 |
| 40 张历史截图 | ≈ 32–44k tokens | ≈ 0.026–0.035 元/问（**8–11 倍**） |

更关键的三点：

1. **发不出去**：主流 API 对单请求图片数量有限制（常见 10–20 张），"把一天的记忆发给模型"根本不可行；
2. **不可本地检索**：文本可以 grep、统计、再摘要（事件→日摘要→周摘要逐级压缩）；像素不能 grep，
   也不能无模型压缩，每次回看都要**再跑一次 VLM**（再花钱、再等 1–5 秒）；
3. **延迟**：读 1 张图约 1–5 秒；读 40 张不可接受。

### ④ 隐私：截图归档是负债

78 MB/月（去重）到 3.78 GB/月（全量）的截图意味着：密码、聊天、银行页、证件照片
全部落盘且越积越多。文本层受隐私红线约束（不复述密钥/金额/聊天原文），且只含语义摘要。
对"陪伴 + 理解"型产品，这决定了：**默认不留截图历史**。

## 12.3 结论（本项目已采用）

1. **长期记忆 = 文本**：L2 事件（323 B/条）→ L1 每日摘要 → L0 对话；可检索、可压缩、可脱敏、召回便宜。
2. **像素 = 原料**：只在两个时刻进入——① 周期理解（画面有变化时）；② "现在/此刻"类提问现场截一张。
   默认仅保留最新一张（可关）。
3. **唯一例外**：当内容本身是**感知性**的（照片 / 设计稿 / 视频帧 / 白板照），文字必然有损，
   这时存图片才是对的——但那不是本产品的主场景。

## 12.4 如果将来仍要"图片记忆"：关键帧存档（可选，未实现）

正确的设计是**关键帧存档**而不是全程录像：

- 频率：每小时最多 1 张（或仅在检测到报错/异常时抓取）；
- 容量：上限 200 张（≈17.5 MB），超限 FIFO 淘汰；按本机基准 ≈ 2.1 MB/月；
- 隐私：默认关闭、`data/screenshots/archive/`、可一键清空、审计脚本覆盖；
- 召回：仅在问题明确指向"回看/截图/报错"时，按日期索引取 1–2 张附给 VLM，而不是批量喂。

比"全量存图"省约 400 倍，且保持了可解释性。需要的话随时可以加（默认不加，避免隐私负债）。

## 12.5 可复现自查

- 设置 → 数据 → 「记忆体积」：文本记忆条数/体积/平均字节、单张截图字节、
  按事件存图的日/月体积——本机数字随时复算。
- `npm test`：`test/stats.test.mjs` 把本机基准固定为回归用例，数字漂了会报警。
