## 变更 5：修复「瞬时状态被固化」与「气泡翻转漏判」（2026-09-27）

- 问题 A：养成数据把 `phase` / `pose` 等运行期瞬时状态一并持久化，重启后会原样恢复。
  实测表现为：上一次退出时处于 work 姿势，重启后一直「抱电脑工作」、
  永不漫游（拖拽以外的位移逻辑全部依赖 idle 状态）。
  修复：`createWhale()` 一律从 idle 开始，瞬时状态由 tick / context 事件重新决定。
- 问题 B：气泡翻转（bubble-below）只在窗口移动时判断，启动时若立绘已贴顶则漏判，
  气泡渲染在屏幕外不可见。修复：新增 `syncEdgeClass()`，在启动、移动、
  窗口尺寸变化三个时机同步。
- 实现位置：`src/renderer/core/state.js`（createWhale）、`src/renderer/pet/pet.js`
  （syncEdgeClass / init / resize）。

## 变更 9：行为逻辑对齐参考项目——不再乱跑（2026-09-27）

依据 dsh-whale-musume 的实际实现（`reference/dsh-whale-musume/assets/whale-moe-core.js`
与 `dsh-whale-moe.js`）重做桌宠行为：

- **位置恒定**：默认不再自主漫游（`companion.walk` 默认 `false`）。参考项目里她从不自己移动，
  位置只由拖拽决定；设置里勾选「允许在桌面走动」可恢复旧行为。
- **原地待机小动作**：借鉴其 `IDLE_ACTION_POOL`，每 45–110 秒随机播放 4.5–8 秒的日常动作
  （喝咖啡 / 伸懒腰 / 摸鱼 / 晒太阳 / 敷面膜…，素材池 13 张），只换图、不移动窗口。
- **动势换图**：借鉴其 motion-hide swap——旧图快速下压（110ms）→ 在最重的一帧换图 →
  新图弹起（240ms，`cubic-bezier(.34,1.3,.64,1)`）；点击/互动反应保持瞬时切换。
- **AFK 打盹**：3 分钟无互动且主人不在工作 → 原地入睡（`napAfk`），任一互动立即唤醒；
  夜间睡眠不受互动影响（不会被"叫醒"成待机）。
- **基础待机图固定为 `idle-cute`**，不再每次重绘随机跳图；随机性只出现在小动作槽位。

实测：43 秒采样窗口内窗口坐标零变化（不乱跑）；65 秒窗口内原地小动作触发 1 次；
38/38 单元测试通过。

## 变更 13：分析结果扩容为 detail/entities/topics + 无障碍树文本摘录（2026-09-28）

- 提出背景：用户指出「图片分析只回几个字」是浪费了图片里的信息；并追问
  「直接传图片不就行了，为什么要套 OCR？」——本变更把两个问题一次说清并落地。
- 结论（写入 docs/10）：
  - **不引入 OCR**：OCR 是"再跑一个模型把像素变成字"，等于额外一层成本与误差；
  - **截图仍是主证据**：布局/图表/报错横幅/视频画面只有 VLM 能读，照旧整张发给云端；
  - **新增的是无障碍树（UIA）文本摘录**：操作系统本来就持有的控件文本（文件名、报错原文、
    页面标题），本机只读、近零成本、是字符级真值，作为请求里的「精确文本提示」随截图一起发。
- 实现：
  - 新增 `src/main/context/uiText.js`：UIA 脚本 + `filterUiTexts`（去空白/去重/限长/剔除疑似密钥）
    + `createUiTextPolicy`（首次 5s、其后 1.4s、失败/空结果 30 分钟负缓存）；
  - `activeWindow.js` 新增 `getUiText()`（失败/超时/空一律 `[]`，绝不抛错、绝不拖慢主链路）；
  - `engine.js` 在分析前取摘录（可关：`context.uiText`），事件新增
    `detail`（具体在做什么）/ `entities`（项目、文件名、关键词）/ `topics`（主题词）三个字段；
  - `analyzer.js` 的云端 schema 与基础感知同步扩展（本地分类也用上文本）；
  - 设置 → 上下文 新增「读取界面文本（无障碍树）」开关；「当前状态」卡片展示 detail/实体/主题。
- 实测（本机，Windows 11 + pwsh 7）：
  - 记事本：199ms / 48 个控件，含完整报错 `找不到 E:\…\20260921.txt 文件。` 与全部标签页文件名；
  - ChatGPT 桌面端（Electron）：首次查询阻塞 10.7s 且返回空 → 这就是必须硬超时 + 负缓存的直接证据。
- 测试：`test/ui-text.test.mjs` 新增（过滤/负缓存策略），`test/analyzer.test.mjs` 扩充
  （无障碍文本参与分类、detail/entities/topics 截断清洗）；全套 60/60 通过。

## 变更 14：让她开口 + 反复读 + 跨天实体记忆（2026-09-28）

- 主人反馈三件事：「很少看到她显示回答」「为什么老是重复摇尾巴」「继续（做跨天记忆）」。
- 根因与修复：
  1. **观察从不说出口**：`note` 此前只写进事件、在设置页展示，桌面上从不开口。
     现在 `main.js` 的 `maybeSpeakNote` 会在感知后按节流策略把观察说出来（桌宠气泡 + 进对话记忆）：
     工作中 8 分钟、其余 3 分钟一条；安静时段、气泡关闭、桌宠隐藏时不说；与最近说过的任何一句过像也不说。
     设置 → 陪伴 新增「把观察说出来」开关（`companion.speakNotes`，默认开）；
     右键菜单新增「让她说一句」（手动触发，走主动搭话的试跑路径）。
  2. **老重复摇尾巴**：三处一起改——
     人设规则写明「MODE_TAIL_FLUKES 是尾巴会表达情绪，不是每句都提尾巴；平均每 5 句最多 1 次」；
     分析提示词附上「最近已用过的观察」并要求换意象；新增 `notes.js` 的 `ensureFreshNote`
     做本地兜底（与最近 5 条相似度 ≥0.55、或尾巴在最近 5 条里已出现 ≥2 次 → 换成同类别本地台词池，

## 变更 15：修掉「桌宠空转烧 CPU / 鼠标拖动发卡」（2026-09-28）

- 主人反馈：「这个项目吃 CPU 大吗？拖动鼠标感觉卡卡的」。
- 实测（本机 24 核，任务管理器口径：单核基准）：
  | 状态 | 渲染进程 | GPU 进程 | 合计 |
  | --- | --- | --- | --- |
  | 改前（待机常驻 bob 动画） | 17% | 10% | **28%** |
  | 加强层提升后仍常驻动画 | 15.9% | 43.6% | **63.6%** |
  | **关掉常驻动画（修复后）** | 0.6% | 0.4% | **1.1%** |
- 根因：**透明置顶窗口上的常驻 60fps 动画**。`#pet` 的 `bob`（待机）/`breathe`（睡眠）
  是 infinite 动画，配合子元素 `drop-shadow` 滤镜，使 Chromium 每秒 60 次重新合成这个
  分层窗口；Windows DWM 随之持续重合成，表现为**拖动鼠标偶尔发卡**（而不是这个进程本身多忙）。
- 修复：
  1. 删除 `bob` / `breathe` 常驻动画；「活着」的手感改为 JS 每 18–40 秒一次、1.6s 的轻微起伏
     （`tickBreath`，只动合成层，不常驻）；
  2. 渲染层的动画循环改为**按需**（`needsAnimation/ensureAnimation`）：只有拖拽惯性滑行、
     走动开启时才挂 rAF；其余时间用 1 秒一次的低频 tick 处理待机小动作与散步调度；
  3. 鼠标穿透命中原先每次 `mousemove` 都调 `document.elementFromPoint`（触发布局），
     改为几何矩形判定（`visualBox` + 菜单矩形）并合并到每帧一次；
  4. `#pet` 加 `will-change: transform`（提前提升合成层），`sway/dangle/pop` 这些短动画保留；
     走动模式（默认关闭）仍是逐帧，设置页已注明会更费电。
- 复测：空转 **1.1%**（渲染 0.6% + GPU 0.4%）；`WHALEPAL_DEBUG_CAPTURE=1` 探针显示
  立绘正常加载（`idle/greet.webp`、spriteBox 33,112,269,348）。

## 变更 17：DSH（DeepSeek Harness）桥接 —— 真的做成了插件，不是挂名（2026-09-28）

- 背景：想被 DSH 生态收录就必须是**真插件**（`dsh.bundle` + `cordis.patch.yml` + 宿主侧 `apply(ctx)`），
  只挂 `dsh-plugin` topic 会被 awesome-dsh-plugin 的 CI 判不合规，而且"搜到装不上"对口碑是负的。
- 实现（对着本机安装的 `@deepseek-ai/dsh@0.1.5-rc.2` 源码写的，事件名逐个核对）：
  1. **新增子包 `packages/dsh-bridge/`**（monorepo 子包，官方 contributing.md 明确支持）：
     `package.json` 声明 `dsh.bundle.patch`，`cordis.patch.yml` 用 `insert` 把自己挂进配置树，
     `lib/index.js` 订阅 `agent/session-start`、`agent/status`、`tools/pre-execute`、`tools/result`、
     `agent/error`、`agent/turn-stopping`、`approval/request`，
     组装成小 payload POST 到回环地址；`lib/state.js` 是纯函数（工具分类、地址校验、节流），可单测。
  2. **隐私红线写进代码**：`normalizeEndpoint()` 只接受 `127.0.0.1` / `localhost`，
     其它地址一律拒绝发送；payload 不含消息内容，最多带 90 字的命令/路径；无遥测、不落盘；
     鲸伴没开时静默失败（每 5 分钟最多一条 debug 日志）。
  3. **鲸伴侧接收端 `src/main/context/dshBridge.js`**：只监听 `127.0.0.1`（默认 8787，可关可改端口），
     8KB 体积上限、字段全部重新校验截断；收到状态 → 广播 `dsh:state` → 桌宠直接切换姿势：
     跑工具 → 对应工作姿势组；报错 → 沮丧反应；回合结束 → 庆祝；等待确认 → 冒一句提醒。
     DSH 忙时它优先于截屏推断（2 分钟内不让屏幕分析抢走姿势）；DSH 关掉则完全退回原来的行为。
  4. 设置 → 陪伴 新增「DSH 桥接（本机回环）」开关 + 端口 + 最近一次状态；`docs/11` 增加"入站监听"条目。
- 安装（本机已实测）：`dsh plugin --profile web add <路径|github:Jessie-1939/whalepal#path:/packages/dsh-bridge>`，
  CLI 会把带 `dsh.bundle` 的依赖自动并进 `dsh.profile.bundles`。
  ⚠️ 已知坑：官方 CLI 在 Windows 下转发给 pnpm 时**不处理带空格的路径**（`形如「带空格的安装路径」` 会被拆开），
  所以本机安装要么用 `pnpm add "file:…"` 后再跑一次 `dsh plugin --profile web ls` 触发对账，要么直接用 git 规格安装。
- 测试：`test/dsh-bridge.test.mjs`（校验/截断/回环地址拒绝/节流 + **真起 HTTP 回环把插件 apply() 的事件送达接收端**的联调），
  全套 81/81 通过。
