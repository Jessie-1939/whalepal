# 10 · 上下文设计（调研 + 决策）

> 回答两个问题：**上下文该以图片形式还是分析后的文本形式给模型？市面上的同类项目是怎么设计的？**
> 本文是 WhalePal 的最终裁决，实现见 `src/main/context/builder.js`（装配）、
> `summaries.js`（L1 缓存）、`engine.js`（采集与 L2 落库）、`chat.js`（消费）。

## 10.1 市面项目调研

| 项目 | 采集方式 | 存储 | 喂给模型什么 | 保留策略 |
| --- | --- | --- | --- | --- |
| **screenpipe**（Rust，YC S26） | 屏幕 + 音频连续采集；**无障碍树优先、OCR 兜底**、语音转写、键鼠与应用切换 | 本地（约 20GB/月），只读 SQLite，MCP/CLI 查询 | 代理/用户在查询时按需检索历史（文本为主，帧可回溯） | 原始数据本地长期保存，按需检索 |
| **OpenAdapt** | 按界面分级：浏览器取 DOM / 无障碍，原生窗口取视觉 + OCR + UI Automation；RDP/VDI 走像素 | 本地 SQLite + 截图目录；带 PII/PHI 清洗模块 | **结构化文本优先、视觉兜底**；录制→回放/编译 | 原始录像默认不出本机 |
| **MineContext**（volcengine） | 周期截屏（可设区域/间隔） | SQLite + 向量库；重复截图删除 | **截图 → VLM → JSON 文本**；摘要/待办/洞察均为文本 | 重复帧淘汰，文本长期保存 |
| **OpenViking**（volcengine，上下文数据库） | 不是采集器 | 虚拟文件系统 `viking://`，每个目录带生成摘要 | **L0 摘要 → L1 概览 → L2 全文** 的目录式分层阅读，按需下钻 | 按目录/子树检索，非平铺向量池 |

**三条共识**：

1. **像素只在"需要看"的时刻进场**：采集时用一次（理解屏幕）、或用户明确要"看某段历史/现在"时按需读取；长期记忆是文本。
2. **分层阅读**：先读摘要（便宜），需要细节再下钻全文。
3. **结构化优先、像素兜底**：窗口标题/无障碍/DOM 这类结构化信息最便宜也最稳；像素只用于结构化拿不到的内容。

## 10.2 WhalePal 的分层上下文（已实现）

### 三层结构

| 层 | 内容 | 载体 | 用途 |
| --- | --- | --- | --- |
| **L0 · 对话与概览** | 最近对话、今日 headline | `data/dialogue.jsonl` | 让"她记得自己刚说过什么、主人有没有回应" |
| **L1 · 每日摘要** | 每天 3–6 条要点（云端生成或本地模板） | `data/summaries.jsonl`，**过去日期生成一次后缓存** | 跨天问答（"昨天/这周"）零重复成本 |
| **L2 · 事件明细** | 时间 / 活动 / 应用 / 是否工作 / 驻留时长 | `data/events.jsonl` | 精确回答"我刚才在干嘛" |

### 投放规则（唯一裁决处：`builder.js`）

| 场景 | 输入形式 | 理由 |
| --- | --- | --- |
| 周期屏幕理解（capture） | **图片** + 前台窗口标题/进程 | 只有 VLM 能读出画面内容；当场转成结构化 JSON 文本落 L2 |
| 普通问答（"我刚才在干嘛"） | **纯文本**（L0+L1+L2） | 图片 ≈ 800–1100 token/张，事件行 ≈ 25–40 token；历史问题不需要重新看像素 |
| 「现在/此刻/屏幕」类问题 | 文本层 + **现场截取的一张截图** | 需要"看"的一刻才付图片成本（实测有效：她能读出当前窗口在做什么） |
| 今日摘要 / 日历单日摘要 | 纯文本；过去日期走 L1 缓存 | 摘要本来就是文本产物，缓存后重复查看零调用 |
| 主动搭话判定 | 纯文本（最近事件 + 对话 + 门控） | 决策不需要像素；默认沉默，靠工具门控发送 |

### 意图识别与装配

`detectIntents(question)`：

- `wantsNow`（现在/此刻/正在/当前/屏幕/桌面…）→ 附实时截图；
- `wantsYesterday`（昨天/昨日）→ L2 换成昨天的明细，并带昨天的 L1 摘要；
- `wantsWeek`（这周/最近几天…）→ 附最近 7 天已缓存的 L1 摘要。

`buildQuestionContext()` 输出三个文本块（`【L2 · 事件明细】/【L1 · 每日摘要】/【L0 · 最近对话】`）
与一个 `attachFreshImage` 标志；`chat.ask()` 按标志决定是否现场截图。

### 成本与隐私

- 成本量级：一次文本问答 ≈ 1.5–2k token（40 条事件 + 摘要 + 对话）；一次"现在"问题 ≈ 再 +1k（截图）；
  一次周期理解 ≈ 0.9–1.2k（截图，且画面未变化时由哈希窗口去重跳过）。
- 隐私：截图默认**只保留最新一张**（可关）；raw 像素只在"周期理解"与"现在提问"两个时刻离开本机；
  发往云端的提示词带隐私红线（不复述密码/密钥/金额/聊天原文）；三层数据全部位于 `data/`，清空记录=三层全清。

### 保留策略

| 数据 | 策略 |
| --- | --- |
| L2 事件 | 上限 5000 条，超限裁剪；每条含 `durationMs` 驻留时长 |
| L1 摘要 | 每天一条（后写覆盖），过去日期生成后不再重复调用 |
| L0 对话 | 上限 400 条 |
| 原始截图 | 仅 `screenshots/latest.jpg` 一张（可关） |

## 10.3 与参考实现的对应关系

- **MineContext** → 哈希窗口去重、重复画面合并为驻留时长、按天热力图（日历）——已移植；
- **OpenViking** → L0/L1/L2 分层与"摘要先行"阅读（本设计的分层来源）；
- **screenpipe / OpenAdapt** → "结构化优先、像素兜底"的采集哲学（我们以窗口标题/进程为主元数据，
  像素用于理解与"现在"提问）。
