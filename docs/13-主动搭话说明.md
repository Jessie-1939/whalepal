# 13 · 主动搭话说明（为什么她"很少说话"）

> 回答一个问题：**她会主动询问吗？为什么一直没见她说过话？**
> 实现：`src/main/context/proactive.js`（门控 + 工具调用）、`src/main/context/care.js`（关怀）、
> `src/renderer/core/lines.js`（台词）、`src/main/main.js`（5 分钟一次的判断定时器）。

## 13.1 她现在会不会主动说话——会，但被三层规则严格约束

主动消息共有三类，全部**默认克制**：

1. **主动搭话**（模型判断值得才说）：每 5 分钟最多评估一次；
2. **主动关怀**（久坐 / 深夜 / 回来打招呼）：规则触发，冷却 ≥15 分钟；
3. **问候**：启动时按时间打招呼（安静时段除外）。

## 13.2 主动搭话的完整门控（任何一条命中都会保持沉默）

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 设置里关闭"主动搭话" | 不发 |
| 2 | 关闭"台词气泡"或桌宠隐藏 | 不发 |
| 3 | **当前处于安静时段（默认 23:00–6:00）** | 不发 |
| 4 | 最近 30 分钟没有任何屏幕记录 | 不发 |
| 5 | **主人正在专注工作（isWorking）** | 不发 |
| 6 | 距离上次主动消息 < 12 分钟 | 不发 |
| 7 | 上次主动消息后主人一直没回应 | 不发（见 13.3） |
| 8 | 未配置云端模型 Key | 不发（没有判断能力） |
| 9 | 以上都通过 | 交给模型判断：**必须显式调用 `send_message` 工具才会发送**；调用 `stay_silent` 或没调用任何工具 = 不发 |

发送前还会做一次本地去重：与最近 20 条中说过的内容重复 → 不发。

## 13.3 未回应与超时信号（TIMEOUT_SIGNAL）

- 发出主动消息后 4 分钟内主人没有任何互动（点她 / 拖她 / 提问都算互动）：
  最多补发**一次**轻量的"在吗"信号（`src/main/context/proactive.js` 的 `TIMEOUT_LINE`）；
- 补发之后：保持安静，直到主人先互动为止（不会再追问）。

## 13.4 为什么你"一直没见她说话"

从实际运行时间线看，最可能同时满足的沉默条件：

1. **安静时段**：你最近几次使用都在 23:00–6:00 之间——这是默认的静默设计（深夜不打扰，
   仅保留每晚一次的"劝休息"关怀）；
2. **工作态不插嘴**：你几乎一直在"工作中"（上下文判为 isWorking），按设计她绝不闲聊；
3. **严格门控**：主动搭话还要通过 30 分钟活跃、12 分钟冷却、未回应等待等条件——
   在有云端 Key 的前提下，她才可能真正开口，且由模型决定"值不值得说"。

问候语也一样：安静时段启动不会打招呼（所以深夜只看到她安静地工作/打盹）。

## 13.5 如何验证她真的会说话

按优先级试任意一种：

1. **和她对话（即时回复，不受主动门控限制）**：设置 → 对话 → 输入"我刚才在干嘛"；
2. **改小安静时段**：设置 → 陪伴 → 安静时段改为 `0 – 6`（或临时改成不覆盖当前时间），
   然后**离开键鼠 5–10 分钟**（或切到非工作页面，如视频/浏览器），等 5 分钟判断定时器命中；
3. **久坐关怀**：连续工作 25 分钟后，必有一次提醒（工作态也允许，属于关怀类）；
4. （规划中）设置 → 对话 → 「让她现在主动说一句」按钮：立即执行一次判断并展示结果
   （发送内容或"为什么保持沉默"）。

## 13.6 设计取舍

她的定位是"陪着，不是指挥"：默认沉默、工作态不插嘴、深夜静默、同信号不重复、未回应不追问。
如果你希望她更活泼，可调整：`companion.proactive`（总开关）、安静时段、
或直接在对话里找她——对话永远即时响应，不受任何主动门控限制。
